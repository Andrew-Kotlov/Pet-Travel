# Возможности и пользовательские маршруты

## Работает в версии 2.0

| Маршрут / действие | Экран и Route | Backend / данные | Проверка |
|---|---|---|---|
| `/` | Главная, переходы в регистрацию и статьи | Публичный статический контент | React, E2E на 360/768/1280 |
| `/articles` | Список 9 статей, поиск и тематические фильтры, пустая выдача | Локальные тексты | React, E2E |
| `/aboutus` | Описание назначения и реальных возможностей | Публичный контент | E2E |
| `/signup?role=parent` / `sitter` | Выбор роли, форма, ошибки, переход в профиль | POST `/api/auth/signup`, bcrypt, сессия PostgreSQL | Unit, integration, E2E обеих ролей |
| `/signin` | Вход, ошибки и повторная попытка | POST `/api/auth/login` | React, integration, E2E |
| Выйти | Кнопка навигации, переход на вход | POST `/api/auth/logout`, cookie и WS аннулируются | Integration, E2E |
| `/profile`, parent | Сохранение своего имени, фото по URL, страны/города, описаний дома и ухода | GET/PUT `/api/profile`; ParentProfiles | Integration, E2E |
| `/profile`, питомцы | Список, добавление, изменение, подтверждение удаления | CRUD `/api/pets`; только собственные Pets | Unit, integration, E2E |
| `/profile`, sitter | Опыт, статус, страна/город, 7 видов животных | GET/PUT `/api/profile`; SitterProfiles | Integration, E2E |
| `/chat` | Ввод ID, карточка контакта, история, отправка, статус соединения, предыдущие сообщения | `/api/chat/*`, `/ws`, Messages | Integration, E2E двумя пользователями |
| Закрытые маршруты | Вход для гостя, загрузка сессии, повтор при ошибке | GET `/api/auth/session` | React, integration, E2E |
| Неизвестный путь | Экран 404 и ссылка на главную | SPA fallback | React, E2E |
| `/photo-credits.html` | Авторы фотографий и лицензии | Статический HTML | Проверка файла и ссылок при подготовке |

На главной нет формы заказа: «Профиль владельца» и «Профиль петситтера» открывают регистрацию с выбранной ролью. У вошедшего пользователя регистрация переводит в существующий профиль; роль не меняется. ID отображается в личном профиле. Для первого диалога люди обмениваются ID самостоятельно — это минимальное завершение исходного чата без выдуманного каталога.

## Что ограничено

- Можно редактировать свой профиль. Полного каталога и страниц чужих профилей нет; чат показывает только имя, роль и фото контакта.
- Фото задаются HTTPS-ссылками; загрузки файлов, хранения изображений и обработки EXIF нет. Основные фотографии интерфейса лежат в репозитории с лицензиями.
- Чат текстовый, для двух пользователей, в одном процессе API. История хранится в БД. Нет вложений, списка всех диалогов, непрочитанного счётчика, блокировок и гарантии exactly-once.
- Сессии восстанавливаются; восстановление/смена пароля, подтверждение почты, изменение роли и удаление аккаунта не реализованы.
- Отзывы, верификация, дополнительные поля старых моделей и календарные даты сохранены в БД, но не представлены работающими услугами в интерфейсе.

## Ещё не реализовано

Поиск ситтеров, календарь доступности, бронирования, оплата, карты, пользовательские рейтинги, процесс проверки личности, модерация и доставка животных. Их добавление требует отдельного продуктового решения, а не декоративной кнопки. Docker, CI/CD, развёртывание и эксплуатация остаются задачами владельца: [передача DevOps](DEVOPS_HANDOFF.md).
